# 特性エンジン（部分実装）

`data/cards/cards.json` に原文を保存し、`scripts/compile-abilities.mjs` が
`data/cards/ability-effects.json` を生成する。同じ原文に対して同じ結果を出す。
生成ファイルは全特性を ID と印刷版ごとに記録する。

- `supported`: 文章全体が登録済みのパターンに一致した特性。
- `needs_review`: 未知の文章。合法手を生成しない。
- カード全体の `engine.status` は別。特性が対応済みでもワザやルールが未対応なら
  カード全体を `supported` にしない。

`src/engine/AbilityEngine.js` は、対応した特性だけについて、
盤面の条件とコストから合法手を生成し、返した行動だけを実行する。
手札から直接ベンチに出す特性、ドロー、手札トラッシュとドロー、
基本エネルギーの特性による追加の装着、受けるワザのダメージ軽減に対応。
前の相手の番のきぜつを条件とするドロー、場にいる間のにげるコスト変更、
場のポケモンの名前と匹数によるワザ使用条件も対応。

きぜつの履歴は `state.previousOpponentTurnKnockout[playerIndex]` に直前の相手の番の
結果を記録する。試験画面は履歴を場面ごとに設定する。通常対戦エンジンへの接続時は
きぜつ処理から記録・ターン更新・期限切れを実装する必要がある。
`retreatCost` は特性反映後のにげるエネルギー数、`abilityAllowsAttack` は
特性によるワザ禁止条件を満たすかだけを返す。エネルギーやワザ自体の合法性は判定しない。

`ability-demo.html` は実DBを読み込む試験画面。通常対戦エンジンではない。
スタジアム、ポケモンのどうぐ、特殊状態、特性を止める効果、ワザ、
きぜつ、サイド取得、山札切れ等の相互作用はまだ扱わない。
未知の特性を持つポケモンが場にいると、この試験エンジンは停止する。
山札が必要なドロー枚数に足りない場合も安全側で候補を出さない。
これらの状態で通常ルールの合法手を網羅したとはみなさない。

実データによる確認: `npm test`。DB更新後の再生成: `npm run compile:abilities`。
